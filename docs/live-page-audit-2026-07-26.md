## نتائج التدقيق

### 🔴 2026-07-26 — مركز الإشعارات (`/HrSettings/NotificationCenter`) = واجهة صمّاء
**الحكم القاطع:** ~20 قاعدة إشعار دورة حياة (عيد ميلاد، ذكرى عمل، ترحيب، إعادة تعيين، وداع، عقود/تجديد/تمديد، تقاعد، فترة تجربة، مخالفات، إجراءات تأديبية، مقابلات نهاية خدمة، شكاوي، انتخابات...) **تُحفظ ولا يقرأها أي مولّد**. نفس فخّ [[shift-type-dead-settings]].

**الأدلة (تتبّع كامل):**
- `LoadNotificationRulesAsync` يُستدعى **حصراً** من `NotificationCenter.cshtml.cs` (OnGet + Toggle) — لا مستهلك آخر بكل الحل (grep قاطع).
- `NotificationDispatcher.DispatchPendingAsync` = **قناة تسليم فقط**: يقرأ `AttendanceNotificationOutbox` (صفوف Email معلّقة) ويُرسلها عبر SMTP. لا يشير لأي نوع قاعدة (Birthday/Contract/Probation).
- `NotificationDispatcherService` (BackgroundService) = يستدعي `DispatchPendingAsync` دورياً فقط. **لا خطوة توليد**، ولا ماسح موظفين لأعياد ميلاد/انتهاء عقود.
- لا يوجد `IHostedService`/كرون يفحص الموظفين ويصفّ إشعارات حسب القواعد.

**ما يعمل فعلاً (منفصل عن المركز):**
- 🟢 إشعارات **الحضور** (`AttendanceNotificationStore.SendAsync`: غياب أسبوعي/نقص — إرسال يدوي من HR) → الصندوق → المُرسِل → بريد. تدفّق كامل شغّال.
- 🟢 إشعارات `SystemNotifications` **الآنيّة** (ردّ مخالفة، إقرار عهدة) → إشعار داخل التطبيق.
- 🟢 قناتا التسليم SMTP + Web-Push مبنيتان ([[external-notification-channel]]).

**الفجوة = المولّد المفقود:** يلزم `IHostedService`/كرون يومي يفحص الموظفين، يقرأ قواعد المركز المفعّلة، يحسب `DaysBefore`، ويصفّ الإشعارات في الصندوق/`SystemNotifications`. ميزة متوسطة الحجم (تستحق جلسة مستقلة)، ليست إصلاحاً سريعاً. **بدونها المركز يعطي انطباعاً خاطئاً بأن الإشعارات مفعّلة.**

> ✅ **مُنجز 2026-07-26 (v1):** أُضيف المولّد المفقود — `NotificationRuleGenerator` + `NotificationRuleGeneratorService` (كرون يومي 08:00 بغداد، لحاق عند الإقلاع). v1 يغطّي القواعد الزمنية الأربع الحقيقية: **عيد ميلاد · ذكرى عمل · قرب انتهاء عقد · قرب انتهاء فترة تجربة** (بقية القواعد الحدثية تحتاج ربطاً بأحداثها لاحقاً). يُطلق عبر **صندوق داخل النظام (`UserNotification`) + Web-Push** للمستلمين (المدير المباشر حسب الجمهور + المشرفون/أدمن-HR). منع تكرار بجدول `ZynoraNotificationEvents` (مفتاح فريد لكل حدث لا لكل يوم). منطق المطابقة الزمنية نقيّ + مغطّى باختبارات. المركز لم يعد صمّاءً.
