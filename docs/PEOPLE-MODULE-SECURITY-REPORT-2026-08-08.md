# تقرير أمن وسلامة مودل «الأشخاص» — People Module Security & Integrity Report

> **التاريخ:** 2026-08-08 · **الفرع:** `claude/smartattendance-local-rebuild-wftwb3`

> **الانحدار:** 1375/1375 ناجح · build Release: 0 أخطاء.

---

## 1. الملخّص التنفيذيّ

خضع مودل «الأشخاص/الموظفين» لتحصينٍ أمنيٍّ إنتاجيّ الغرض منه توحيد التخويل بحيث:

> **النطاق الفعّال للموظف = نطاق صلاحية People ∩ نطاق «موظفي أدوار الوصول»**، مُنفَّذاً
> **على الخادم** لا بإخفاء الواجهة، **فاشلاً مغلقاً** (fail-closed).

أُغلقت **تسع نقاط ضعف** موزّعة على القراءة والكتابة والتصدير والاستيراد، كلٌّ بكوميت
مستقلّ واختبارات. لم تُمَسّ صيغ الرواتب/الحضور ولا بيانات الإنتاج ولا أي مودل غير
«الأشخاص». الآلية المعماريّة الأساسية (تقاطع النطاقين عبر `EffectiveScopeService`)
كانت موجودة؛ العمل كان **تطبيقها** باتّساقٍ على كل مسارات المودل.

## 2. نموذج التهديد ومبادئ الإنفاذ

| المبدأ | التطبيق |
|--------|---------|
| رؤية الواجهة ليست أمناً | كل قرار يُعاد تقييمه على الخادم في `OnGet/OnPost` |
| الفشل المغلق | حرمانٌ كليّ ⟹ لا صفوف/`Forbid`؛ الغموض يُقيِّد لا يوسّع |
| التقاطع لا التوسيع | أدمن/«All»/بلا دور بيانات ⟹ غير مقيَّد، فالتقاطع **يضيّق فقط** |
| العزل بمستوى SQL حيثما أمكن | `ApplyPeopleDataScope` predicate مترجَم لـSQL قبل العدّ/الترقيم |

**حقيقة مخطط محوريّة:** كيان `Employee` **بلا عمود `CompanyId` مباشر** — الشركة تُشتقّ
عبر `Branch.CompanyId`. كل استعلامات النطاق تصل الجدول بالفروع. (تفصيل بـ
`docs/COMPANY-ISOLATION-AUDIT.md`.)

## 4. الآليّات المضافة (سطح الكود)

- **`PeoplePermissionCodes.ViewCompensation` / `EditCompensation`** — رمزا التعويض،
  ضمن «محروم التوافقية».
- **`EmployeeListQueryViewModel.AccessRoleScope`** — يُقاطَع (AND) مع `DataScope` داخل
  `EmployeeService.GetPagedAsync` بتطبيق `ApplyPeopleDataScope` مرّتين.
- **`PeopleDataScope.AllowsLocation(companyId, branchId, departmentId)`** — فحص وجهةٍ
  **موقعيّ** (بلا معرّف موظف). ضروريٌّ لأن `AllowsEmployee` يرفض المعرّف الصفريّ، فلا يصلح
  لفحص «أين يُسمح بإنشاء موظف».
- **`EmployeeBootstrapImportEngine.ImportScope` + `EvaluateRowScope` (نقيّ)** — قرار فرض
  النطاق لصفٍّ واحد، قابلٌ للاختبار وحدةً بمعزلٍ عن قاعدة البيانات.
- **`TemplateExportScope`** — نطاق التصدير + علم إدراج الراتب.

## 6. المخاطر المتبقّية والقيود المُعلَنة (لا ندّعي أكثر مما نفرض)

1. **تصادم المعرّفات عبر الشركات** — نطاق «OwnCompany» يسمح بمطابقة القسم؛ إن تصادف
   معرّف قسمٍ بشركةٍ ما مع قسمٍ بأخرى فقد يتسرّب. موثّقٌ صراحةً باختبار
   `CrossCompanyBranchCollision_DoesNotLeak`. العلاج البنيويّ (عمود `CompanyId` مباشر على
   `Employee`) خارج نطاق P0.
2. **قرار «الفرض الصارم» للاستيراد** قد يضيّق وركفلو HR اعتمد على استيرادٍ واسع النطاق —
   قرارٌ عمليّ معتمد من المالك.
3. **اختبارات العزل الحيّة** للداشبورد/التصدير/الرؤساء/الاستيراد لم تُضَف بعد (المُضاف
   اختبارات دلالة نطاقٍ نقيّة). مستحقٌّ على نمط `TenantIsolationIntegrationTests`.
