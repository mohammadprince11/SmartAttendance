## 0) الخلاصة بثلاثة أسطر

1. مودل الرواتب بكيان ليس «شاشات كثيرة» — بل **محرّك صيغ واحد** تُغذّيه
   **فضاء متغيّرات موحّد (~21 متغيّراً محسوباً + كل عنصر راتب)**، وكل شاشة مالية
   ليست إلا واجهةً تكتب صيغةً بهذا الفضاء.
2. عندنا **المحرّك موجود وجيّد** (`SalaryFormulaEvaluator`) — الناقص هو **الفضاء**:
   نمرّر 7 متغيّرات فقط، **واثنان منها يُمرَّران أصفاراً بالمسير الفعلي**.
3. أخطر ما كشفته الدراسة **ليس نقصاً بل عطلاً**: مختبر الصيغ يعطي نتيجةً،
   والمسير يعطي نتيجةً أخرى لنفس الصيغة. التفصيل بالقسم 7.

## 1) البنية الحاكمة — «الصيغة هي وحدة البناء»

بكيان، هذه الشاشات كلها **نفس المكوّن**: منشئ صيغة برأس (اسم/فعّال/عملة) وجسم
تعبير يُبنى بالنقر لا بالكتابة:

| الشاشة | ما الذي تكتبه الصيغة |
|---|---|
| عناصر محسوبة `ComputedFormula/1` | قيمة معرَّفة تُعاد استعمالها كمتغيّر |
| صيغ التجميع `ComputedFormula/2` | تجميع زمني (معدل/مجموع/عظمى/صغرى/عدد) على فترة سابقة |
| عناصر الراتب (10 أنواع) | قيمة العنصر |
| ملفات الضريبة | الخصم لكل شريحة + الراتب الخاضع |
| إعفاءات الضريبة | قيمة الإعفاء |
| الضمان الاجتماعي | **وعاء** راتب الضمان |
| مكافأة نهاية الخدمة | **وعاء** راتب المكافأة |
| الحد الأعلى للاقتطاع الشهري | سقف الاقتطاع |
| الحد الأعلى للعمل الإضافي | سقف الأوفرتايم |
| عناصر محسوبة بالبنوك / بربط ERP | حقول ملف التصدير |

**الاستنتاج المعماري:** لا تُبنى «ميزة» لكل واحدة من هذه — يُبنى **فضاء متغيّرات**
ومنشئ صيغة، ثم تصير كل واحدة حقلاً نصّياً واحداً بجدول.

### 1.1 منشئ الصيغة (الشكل الفعلي)

- الجسم **رقائق (chips)** لا نصّ حرّ: متغيّر = رقاقة ورديّة، عامل = رقاقة زرقاء،
  الأرقام نصّ. النقر على ⊕ بجانب المتغيّر يدرجه.
- **لوحة مفاتيح ثابتة:** `Floor · Ceil · Round · Is Null · Null If · Abs · If ·
  else If · then · else · end · and · or` والعوامل
  `> >= < <= in , x ÷ + - = != ( ) % c` والأرقام.
- **قائمة متغيّرات قابلة للبحث** على اليمين.
- **«إختبر الصيغة»** = تحقّق نحويّ فوريّ: الجسم **يصير أخضر** إن صحّت (جُرّب حياً
  بصيغة `الراتب الأساسي × 7`). لا يحسب قيمة على موظف — تحقّق نحوٍ فقط.
- **«ملاحظة»** حقل حرّ على كل صيغة.

### 1.2 فضاء المتغيّرات (المكسب الأكبر من الدراسة)

استُخرج من شاشة **«الحد الأعلى للاقتطاع الشهري»** وهي **أوسع** فضاءً من غيرها:

| المجموعة | المتغيّرات |
|---|---|
| الأساس | الراتب الأساسي · العلاوات · **الراتب المستحق** · **العلاوات المستحقة** |
| الحركات | العمل الإضافي · حركة دخل · بدل الإجازة · الإقتطاعات الدائمة · حركة اقتطاع |
| النظامي | التأمين الصحي للموظف · الضمان الاجتماعي للموظف · **الضرائب** · **القروض** |
| الإجماليات | **مجموع الدخل** · **مجموع الإقتطاعات** · **صافي الراتب** |
| الفروقات | فروقات الدخل · فروقات الإقتطاع · فروقات التأمين الصحي · فروقات الضمان |
| الزمن | **عدد أيام الشهر** · أيام العمل · **أيام العمل الفعلية** · `Non Working Days` |
| السلم | سلم الرواتب (أدنى/أعلى/منتصف/أساسي) × (أساسي/إضافي) = 8 |
| الكتالوج | **كل عنصر راتب معرَّف** يصير متغيّراً باسمه |

وبسياق الأوفرتايم تحديداً تُضاف: **سعر ساعة العمل · راتب الضمان الاجتماعي ·
عدد الساعات · ساعات العمل**.

> ⚠️ الفضاء **يتغيّر بحسب السياق**: صيغة الضمان لا ترى «الضمان الاجتماعي للموظف»
> (وإلا لدارت على نفسها). فالفضاء **مُعرَّف لكل نقطة استدعاء** لا قائمةً عالمية.

### 1.3 صيغ التجميع (`FormulaPoolIndex?PageType=2`) — غائبة عندنا كلياً

| الحقل | القيم الحيّة |
|---|---|
| المصدر `SourceID` | حركات الرواتب · حركات الراتب — القيمة المتبقية |
| الدلالة `FunctionTypeID` | **معدل · عدد · قيمة عظمى · قيمة صغرى · مجموع** |
| احسب لمدة `PeriodTypeID` | **سنوات سابقة · أشهر سابقة · أيام سابقة** + عدد |
| تشمل الفترة الحالية | نعم/لا |
| القيمة | صيغة كاملة بفضاء متغيّرات موسّع |

**لماذا تهمّ:** «متوسط الراتب لآخر 12 شهراً» و«مجموع الأوفرتايم للسنة» و«أعلى
راتب خلال الخدمة» — أوعية مكافأة نهاية الخدمة وبدل الإجازة تُبنى بها. عندنا كل
حساب تاريخي يُكتب كوداً مخصّصاً.

|---|---|---|

| 3 | العمل الإضافي | نقدي أو **رصيد إجازة** |
| 4 | الدخل القائم على الحصص | **شرائح** + تراكمي |
| 9 | تعديل أيام الراتب | **تعريف قيمة اليوم بنسبة من عناصر مختارة** |
| 5 | عناصر خارجية | وعاء لقيمة تأتي من خارج النظام (رمز `EXD-n`) |

| 11 | إمتيازات سنوية | استحقاق سنويّ بتاريخ قطع |

### 2.1 حقول نموذج «الدخل» (المرجع)

**تبويب المعلومات الأساسية:** الاسم (عربي + لغة أخرى) · **النطاق** (علاوة /
حركة دخل) · **نوع الدفعة** (داخل الراتب / خارج الراتب) · **قيمة الدخل**
(ثابت / المعادلة) → القيمة + القيمة الافتراضية · **حالة الضريبة** (خاضع /
غير خاضع — وبالاقتطاعات أربع: خاضع / غير خاضع / **معفى** / **معفى بشكل كامل**) ·
يشمل الراتب الإضافي · **الأجر الشامل** · **نسبي** · نشط · **العملة** ·
**رقم الوحدة** · ملاحظة.

**تبويب القواعد** = قواعد تحقّق: **فترة الصلاحية (من/إلى) · القيمة الدنيا ·
القيمة القصوى**.

**تبويب معايير الاستحقاق** = محرّك الشروط العام — «مجموعة قواعد جديدة» بـ**39
معياراً** (وحدات الأعمال · الموقع · الهيكلية · الحالة الاجتماعية · الجنس ·
الديانة · الجنسية · العمر · مدة الخدمة · المسمى · نوع العقد · نوع العمل · طبقة
العمل · ذوي الاحتياجات · الموظفين · الراتب الأساسي · مجموعات الموظفين · سلم
الرواتب · كفيل · **مواطن** · مراكز التكلفة · الراتب الكلي · مجموع العلاوات ·
مدة فترة التجربة · التصنيف الوظيفي · هيكلية الإعارة · سلم الراتب الإضافي ·
تاريخ التعيين · نوع الدوام · البعد الأول/الثاني/الثالث · في فترة التجربة ·
البنك · التأمين · الحالة · نوع الإعاقة · زمرة الدم …).

### 2.2 خصوصيات تستحقّ النقل

- **الأوفرتايم:** الفضاء يضمّ `سعر ساعة العمل / عدد الساعات / أيام العمل /
  ساعات العمل` + **تنسيق الأرقام** (كسور عشرية · دنيا · قصوى · معدل) +
  **«الحركات قبل/بعد تاريخ القطع تؤثر على: تاريخ الحركة | تلقائياً»**.
- **تعديل أيام الراتب:** تختار **أي عناصر الراتب** تدخل بقيمة اليوم **وبأي نسبة
  %** لكلٍّ منها، ونوع القيمة (دخل / اقتطاع / كلاهما) + تؤثر على الراتب الإضافي.
- **الحصص:** شرائح + **تراكمي** — أي عمولة/حافز إنتاج بشرائح بلا كود.
- **قيم ثابتة:** جدول اسم↔قيمة. بدونه تُكتب أرقام سحرية داخل عشرات الصيغ.

- **معالج الترقية:** خطوة 1 (الموظف · العملة · السلم الحالي/الجديد · تاريخ

## 6) دورة المسير (`MonthlySalaryCalculation`)

**الشبكة:** رقم الدفعة (`2026-8-1`) · نوع الراتب · الفترة · حوسب بواسطة + ختم
زمني · عدد الموظفين · مجموع الرواتب · **مقفل · تم إصدارها · تم إرسال القسيمة**
(ثلاث رايات دورة حياة منفصلة).

**إجراءات الصفّ:** عرض · حذف · **إقفال** · **إعادة الإحتساب** · ملاحظة.

**نموذج الإنشاء — النطاق (13 محدّداً):** الموظفين (منتقٍ) · **الموظفين من جدول
بيانات (ملف)** · وحدة عمل · الهيكلية · الموقع · مجموعة الموظفين · كفيل · مراكز
التكلفة · العملة · نوع العمل · نوع الدوام · الجنسية · المسمى الوظيفي · مناوبة.
ثم: الفترة/السنة · **العلامات (tags)** · **تاريخ الدفع** · **تعديل تاريخ القطع**
· ملاحظة.

**شاشة الدفعة — ثلاثة تبويبات:**
1. **الرواتب المحتسبة** — شبكة 500/صفحة بتجميع بالسحب.
2. **عرض لوحة المعلومات** — لوحة مؤشّرات للدفعة.
3. **الرواتب المستثناة** — ⭐ **الموظف + تاريخ التعيين + سبب الاستبعاد نصّاً**
   («تم توقيف راتب الموظف لعدم وجود عودة إلى العمل» · «الموظف ليس لديه معلومات
   استئناف العمل بعد الإجازة»).

**التهيئة (`Configuration`):**
- موافقات اللجنة لـ: حساب الرواتب · احتساب خارج الرواتب · حساب الاحتياطي ·
  تسوية إنهاء الخدمة · **وحركات مالية مختارة**.
- احسب الحركات السابقة غير المضمّنة · اعتماد تاريخ التنفيذ = تاريخ الموافقة
  النهائية · حساب الاحتياطي على أساس حساب الراتب · **احتساب الرواتب السابقة
  للمعيَّن بأثر رجعي** · احتساب الحركات بالراتب المدفوع مسبقاً.
- **وصول الموظف لقسيمته بعد: إقفال الرواتب | إصدار الرواتب**.
- حالة الموظف عند الانتقال لإنهاء الخدمة · رواتب سابقة بتسوية نهاية الخدمة ·
  عنصر الأجر المتغيّر المرتبط بالأداء · عنصر رسوم الخدمة · الحركات المطبقة على
  غير النشطين.
- سلم الرواتب: تعيين تلقائي بالموقع الوظيفي · ملء قيمة الزيادة المقترحة تلقائياً.
- **حساب الراتب اليومي: كل أسبوعين | أسبوعي | يومي**.
- أمني: إشعار عند تغيير إعدادات الرواتب لـ«المشرف الأعلى» على **27 نوع تغيير**.

**نظام المحاكاة (`KayanSimulator`):** نفس منتقي النطاق الثلاثة عشر + «ما عناصر
الراتب التي ترغب بمحاكاتها؟» (العلاوات · الامتيازات خارج الراتب · الاقتطاعات
الدائمة) ⟵ تحليل what-if قبل القرار. **مدقّق حركات كيان** شاشة مستقلة.

**الحدود القصوى:** «الحد الأعلى للاقتطاع الشهري» يربط **عنصر اقتطاع بعينه**
بـ**صيغة سقف**. الموجود حياً: «الحد الأعلى ← اقتطاع قسط القرض».

**شاشات المتابعة (Screening):** نمط متكرّر — عرض **عابر للموظفين** لإسنادات عنصر
راتب: (الموظف · عنصر الراتب · من–إلى · المبلغ · الحالة) مع إنشاء من نفس الشاشة.
موجود لـ: العلاوات · التسديدات · الامتيازات خارج الراتب · الاقتطاعات الدائمة ·
الامتيازات السنوية · التأمين الصحي · علاوات الموقع.

## 7) 🔴 ما كشفته المطابقة بالكود — عطل حقيقي لا فجوة

### 7.1 فضاء متغيّرات المسير مبتور — واثنان منه صفران دائماً

`SalaryItemStore.FormulaVars` يُعلن للمستخدم سبعة متغيّرات:
`Basic · Allowances · Gross · Hours · Days · DailyRate · HourlyRate`.

و`PayrollRunStore` عند احتساب عناصر المعادلة يبني القاموس هكذا
(`PayrollRunStore.cs` — قسم «محرك الصيغ»):

```
["Hours"] = 0,
["Days"]  = 0
```

**بينما** في نفس الدالة وفي نطاق المتغيّر ذاته تتوفّر فعلياً: `workDays` ·
`absentDays` · `unpaidLeaveDays` · `month.PresentDays` · `month.WorkedHours` ·
`factor` · `daysInPeriod` · `proratedBasic` · `incomeTotal` · `overtimeTotal` ·
`leaveEncashTotal` · `salaryDaysAdd/Deduct`.

**الأثر:** أي عنصر راتب صيغته تستعمل `Days` أو `Hours`:
- `Basic / 30 * Days` ⟵ **صفر دائماً** فيُتخطّى البند بصمت.
- `Basic / Days` ⟵ **قسمة على صفر** ⟶ الصيغة تفشل ⟶ **البند يُتخطّى بصمت**
  (`TryEvaluate(...) out _` — الخطأ مُهمَل).

### 7.2 المختبر يكذب على المسير

`Pages/HrSettings/Formulas.cshtml.cs` يوثّق نفسه بأنه يمرّر **«نفس ما يمرّره
المسير حرفياً، لا قائمةً موازية»** — ثم يمرّر `Hours = 8` و`Days = 30`.

فالنتيجة: **صيغة تُجرَّب بالمختبر فتعطي رقماً، وتُحفظ، ثم تعطي بالمسير رقماً
آخر (أو تختفي).** وهذا أسوأ أنواع الأعطال المالية: صامت، ومُطمئِن.

## 8) ما نتفوّق به (تثبيتاً)

- **ربط الحضور بالمسير بسياسة معلنة** (`AttendanceSalaryLink` بثلاثة أنماط
  وإعلان دائم بالقسيمة) — كيان يستبعد بصمت ويشرح بالنصّ، ونحن نعلن السياسة.
- **مركز الطلبات المالية** — لا نظير له بكيان.
- **تركيب أوعية الاحتساب بيانات** (`SalaryBaseComposer`) — نفس فكرة كيان
  بتنفيذٍ أنظف (عضوية معلنة قابلة للتحرير).
- **بناء الاعتماد الشهري قبل القراءة** (`BuildMonthAsync`) — يمنع «راتب كامل
  بصمت» عند غياب صفّ الاعتماد.

## 10) ما نُفِّذ فعلياً بهذه الجلسة

راجع `docs/HANDOFF-2026-08-08.md` والكوميتات. الملخّص:

1. **`PayrollFormulaVariables`** — مصدر حقيقة واحد لفضاء متغيّرات الرواتب:
   الكتالوج (المفتاح · التسمية · الوصف) **والبنّاء** الذي يُنتج القاموس. المسير
   والمختبر صارا يستدعيانه، فاستحال أن يفترقا مرّةً أخرى.
2. **إصلاح `Hours`/`Days`** — يُمرَّران من بيانات الاعتماد الشهري الفعلية بدل
   الصفر، وأُضيف 12 متغيّراً جديداً بفضاء المسير.
3. **سقف الاقتطاع الشهري** — حارس يمنع أن يتجاوز مجموع الاقتطاعات نسبةً من
   الصافي، مع بند إعلان بالقسيمة.
4. **`PayrollRunExclusions`** — كل موظف مستبعَد يُسجَّل باسمه وسببه، ويُعرض
   بتبويب مستقلّ بشاشة الدفعة.
