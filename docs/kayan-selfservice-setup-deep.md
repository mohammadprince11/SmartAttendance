## 1) الأقسام السبعة بالصفحة

### أ. إعدادات منشورات الحائط

| الحقل | النوع | الحيّ |
|---|---|---|
| السماح بمشاركة المنشورات على الجدار الاجتماعي عبر بوابة الخدمة الذاتية | شيك | ✅ |
| **من يمكنه مشاركة المنشورات؟** `WhoCanSharePosts` | راديو | **جميع الموظفين** / موظفين محددين |
| **يتم مشاركة المنشورات مع** | راديو | **جميع الموظفين** / **الموظفون في نفس وحدة العمل** |

### ب. اقتراحات وشكاوى

`عدم السماح بتقديم اقتراحات وشكاوى كمجهول` — شيك (الحيّ: مغلق ⟹ **المجهول مسموح**).

### ج. حالات المخالفات

`السماح للموظف باختيار الشهود من` `WitnessesTypeID` — قائمة:
**جميع الموظفين** / **الموظفون في نفس الوحدة الهرمية**.

> ⟹ الموظف المتَّهم **يختار شهوداً** — تفصيل قانوني ينسجم مع منظومة المخالفات
> (حق الدفاع · مهلة الاعتراض) التي درسناها.

### د. مستويات فريقي ⭐

| الحقل | التفصيل |
|---|---|
| `السماح للمديرين بالحصول على صلاحية على الموظفين بـ` | شيك ✅ مفعّل |
| `TeamLevels` | قائمة: **1..10** أو **«اخر وحدة»** (الحيّ: اخر وحدة) |
| **الأقسام التي يحصل المدير على صلاحية لها** `lstSectionsOfPermission[]` | ستة شيكات، كلها مفعّلة: **التقويم والرسومات البيانية · قائمة وملفات الموظفين · الطلبات · الحضور · التقارير · بطاقات المواهب** |

⟹ صلاحية المدير على فريقه **ليست كل-أو-لا**: عمق هرمي محدَّد × أقسام محدَّدة.

### هـ. تهيئة طلبات تعديل المعلومات ⭐

| الحقل | التفصيل |
|---|---|
| `المرفق مطلوب عند طلب الموظف تعديل` | شيك (الحيّ: مغلق) |
| **`إختر بند`** — اختيار متعدد | **12 بنداً**: الكفاءات · الخبرات · الشهادات · التعليم · دورات تدريبية · الملفات الطبية · العهد · العناوين · الشركاء · الأبناء · الأقارب · البنوك الأخرى (+ «اختيار الكل») |
| `ملف الإلتزام البنكي إلزامي عند طلب الموظف تعديل معلومات الدفع` | شيك |

⟹ **المرفق ليس قراراً واحداً بل قائمة بنود**: تعديل «البنوك الأخرى» قد يتطلب
مرفقاً بينما تعديل «العنوان» لا.

### و. طلب نقل موظف

`السماح للمديرين باختيار مدير مباشر جديد من قائمة الموظفين كاملة عند طلب نقل
الموظف، بغض النظر عن دور وصول البيانات`.

> نفس استثناء «اختيار المدير» الذي رأيناه بـ`/Employees/Configuration` — يتكرّر
> هنا لسياق النقل. عندهم قاعدة ثابتة: **اختيار المدير يتجاوز نطاق البيانات**.

### ز. تطبيق الهاتف ودليل الموظفين

- `السماح بأخذ لقطات الشاشة وتسجيلها داخل التطبيق` — شيك (منع التصوير = حماية بيانات).
- `دليل الموظفين: إظهار الحالة اليومية للموظف` — شيك (يظهر «حاضر/بإجازة» بالدليل).

## 2) المقارنة حقلاً بحقل

صفحتنا تحوي: `AllowWallPosts` · `EmployeeFeelingAudience` ·
`DisableAnonymousSuggestions` · `AllowManagersTeamAccess` · `ManagerAccessLevel` ·
`AccessEmployees` · `AccessRequests` · `AccessAttendance` · `AccessReports` ·
`AccessCards` · `AccessEvaluations` · `RequireAttachmentOnInfoChange` ·
`RequireBankAttachment` · `AllowDirectManagerTransfer` · `AllowMobileScreenshots` ·
`ShowDailyStatus`.

| العنصر | كيان | عندنا |
|---|---|---|
| السماح بمنشورات الحائط | ✅ | ✅ |
| جمهور المشاركة (الكل / نفس الوحدة) | ✅ | ✅ `EmployeeFeelingAudience` |
| **من يمكنه النشر (الكل / محددون)** | ✅ | ❌ |
| منع الاقتراحات المجهولة | ✅ | ✅ |
| **شهود المخالفة (الكل / نفس الوحدة)** | ✅ | ❌ |
| صلاحية المدير على فريقه | ✅ | ✅ |
| عمق المستويات (1..10 / آخر وحدة) | ✅ | ✅ `ManagerAccessLevel` |
| الأقسام الستة | ✅ | ✅ (عندنا `AccessEvaluations` بدل «التقويم والرسومات») |
| المرفق مطلوب عند تعديل المعلومات | ✅ | ✅ |
| **تحديد البنود الـ12 التي تتطلب مرفقاً** | ✅ | ❌ **شيك واحد عام عندنا** |
| ملف الالتزام البنكي | ✅ | ✅ |
| نقل الموظف: تجاوز نطاق البيانات | ✅ | ✅ |
| منع لقطات الشاشة بالتطبيق | ✅ | ✅ |
| إظهار الحالة اليومية بالدليل | ✅ | ✅ |

**13 من 16 متطابقة.** الناقص ثلاثة:

1. **تحديد بنود المرفق (12 بنداً)** — الأهم عملياً: اليوم إمّا نطلب مرفقاً لكل
   تعديل أو لا نطلبه أبداً؛ والصحيح أن الوثائق والبنوك تحتاج مرفقاً والعنوان لا.
2. **من يمكنه النشر على الحائط** (الكل / محددون).
3. **مصدر اختيار الشهود** بحالات المخالفات — مرتبط بمنظومة المخالفات التي
   ينقصنا منها الجانب الإجرائي أصلاً.

الذي يجب تعميمه عندنا: حيثما وضعنا `bool`، اسأل هل الصحيح `list`.
