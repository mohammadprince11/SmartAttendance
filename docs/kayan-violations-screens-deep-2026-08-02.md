**المصدر:** `demo.kayanhr.com/Employees/Violations/Index?PageType=1` و`?PageType=2`
**التاريخ:** 2026-08-02 · **الطريقة:** فحص حيّ زرّاً زرّاً (شجرة الوصول + لقطات)
**النسخة المفحوصة:** KayanHR 7.1.2

> **الخلاصة بسطر:** واجهتهم **أبسط** من واجهتنا (شبكة واحدة قابلة للتحرير وزرّ
> «صفّ جديد»)، لكنّ **نموذج الجزاء عندهم أعمق بكثير**: نوع الإجراء مُعدَّد لا نصّ
> حرّ، والخصم يُركَّب من وعاء رواتب أو صيغة، ويُرحَّل إلى **عنصر راتب مسمّى**،
> وله سياسة إسقاط بمرساة زمنية. الفجوة الحقيقية عندنا **ليست بالشكل بل بالجزاء**.

## 2) شاشة «فئات المخالفات» (`PageType=1`)

### الترويسة (من اليمين لليسار)
`فئات المخالفات` (عنوان) · `بحث` (حقل) · ✎ (أيقونة تحرير) ·
**[فئة مخالفة جديدة]** (زر داكن) · **[حفظ]** (زر أخضر)

### الجدول

| العمود | النوع | ملاحظات |
|---|---|---|
| ☐ | checkbox | تحديد جماعي (للحذف) |
| فئة (English) | **input نصّي داخل الصفّ** | قابل للتحرير مباشرةً |
| فئة (العربية) | **input نصّي داخل الصفّ** | ثنائية اللغة إلزامية |
| معايير الاستحقاق | منسدلة «اختر» | نفس محرّك الشروط العام |

### السلوك المرصود
- **كل الصفوف حقول إدخال حيّة** — لا وضع «عرض» ثم «تحرير». الشبكة **نموذج واحد**
  و**[حفظ] واحد يحفظ كل الصفوف دفعةً واحدة**.
- **أول صفّين معطّلان (رماديان)**: `Time Attendance / الحضور و الغياب` و
  `Performance Appraisal / تقييم الاداء` — **فئات نظام** لا تُعاد تسميتها ولا تُحذف،
  لأن المحرّك الآلي يولّد عليها.
- **[فئة مخالفة جديدة]** ⟵ **يُلحق صفّاً فارغاً بأسفل نفس الجدول** فيه حقلا الاسم
  وعلامة **✖** لإزالة الصفّ غير المحفوظ. **لا مودال ولا صفحة.**
- الصفّ الجديد **بلا منسدلة «معايير الاستحقاق»** حتى يُحفظ (تُضاف بعد وجود معرّف).
- الجدول يصير قابلاً للتمرير داخلياً بأسهم بحافته عند تجاوز الارتفاع.

## 4) شاشة تفاصيل المخالفة (من زرّ •••)

تنزلق كصفحة كاملة بترويسة `→ مخالفة` + **[حفظ]**.

### القسم العلوي

| الحقل | النوع | ملاحظة |
|---|---|---|
| فئات المخالفات | نصّ للقراءة | سياق فقط |
| مخالفة | نصّ للقراءة | سياق فقط |
| **قالب الرسالة عند الأتمتة** | منسدلة | القالب الذي يُرسَل حين تُولَّد المخالفة **آلياً** |
| معايير الاستحقاق | منسدلة | |
| الوصف | textarea | |

### القسم السفلي — **برنامج التأديب التدريجي**

زر **[+ قاعدة إجراءات تأديبية جديدة]**، ثم قائمة صفوف:

```
◯  المخالفة الأولى    تنبيه شفوي                                   ✎ 🗑
                      إسقاط الإجراءات التأديبية للموظفين بعد 1 سنة (سنوات)
◯  المخالفة الثانية   تنبيه شفوي
                      إسقاط الإجراءات التأديبية للموظفين بعد 180 أيام
◯  المخالفة الثالثة   تنبيه شفوي   … بعد 180 أيام
◯  المخالفة الرابعة   تنبيه شفوي   … بعد 6 شهور
```

**سلّم تكرار بترقيم تلقائي**: قاعدة واحدة لكل حدوث (أولى · ثانية · ثالثة…)،
ولكلٍّ إجراؤها **ومدّة إسقاطها المستقلّة**. لكل صفّ ✎ تعديل و🗑 حذف.

## 5) مودال «قاعدة إجراءات تأديبية جديدة» — القلب

العنوان يُرقّم نفسه: **«اختر الإجراء التأديبي الواجب اتخاذه بشأن المخالفة الخامسة»**.

### الحقول الثابتة

| # | الحقل | النوع | التفاصيل |

| 2 | **نوع الإجراء** | منسدلة | القيم السبع أدناه |
| 3 | **إسقاط الإجراء التأديبي** | مفتاح تبديل | مغلق افتراضياً |
| 4 | **قالب الرسالة** | زر «إختر بند» | منتقي بنود/قوالب |
| 5 | **قالب الرسالة عند الأتمتة** | منسدلة | قالب المسار الآلي |
| | **[حفظ] [إلغاء]** | | |

### 5-أ) قيم «نوع الإجراء» السبع (بمعرّفاتها الحيّة)

### 5-ب) ما يظهر عند تشغيل «إسقاط الإجراء التأديبي»

| الحقل | القيم |
|---|---|
| نمط الإسقاط | ◉ **مرة واحدة فقط** / ◯ **دوريّة** |
| **يسقط بعد** / **يسقط كل** | رقم + وحدة: `أيام` · `شهور` · `سنة (سنوات)` |
| المرساة | **«من تاريخ الإجراء التأديبي»** — ومنسدلة ثانية تضيف: `تاريخ قطع الحركات` · `نهاية السنة التعاقدية` · `نهاية السنة الماليّة` |

### 5-ج) ما يظهر عند اختيار «إنهاء الموظف»

| الحقل | القيم |
|---|---|
| **سبب الإيقاف** | `اختياري` · `انتهاء العقد` · … |

### 5-د) ما يظهر عند اختيار **«اقتطاع من الراتب»** ← المطلوب

| # | الحقل | النوع | القيم / التفاصيل |
|---|---|---|---|
| 1 | **عنصر الراتب** | منسدلة | `حركة اقطاع` · `Penalties` · `اقتطاع قسط القرض` — **العنصر الذي يُرحَّل إليه الخصم بالمسير** |
| 2 | **عدد الأيام** | رقم | عدد أيام الخصم |
| 3 | **نوع القيمة** | راديو | ◉ **نسبة** (False) / ◯ **المعادلة** (True) |

#### إذا «نسبة» ⟵ **وعاء الخصم المركَّب**

سطر إرشادي: *«إختر عناصر الراتب التي تدخل في حساب قيمة الخصم, وحدد النسبة لكل منها.»*

ثم **قائمة بكل عناصر راتب الشركة**، لكلٍّ **☑ تفعيل** و**حقل نسبة %**:

```
☐ الراتب الأساسي            [ 0 ] %
☐ بدل المواصلات             [ 0 ] %
☐ بدل نادي صحي              [ 0 ] %
☐ بدل سكن                   [ 0 ] %
☐ بدل طعام                  [ 0 ] %
☐ بدل سكن 3 اضعاف الراتب    [ 0 ] %
☐ سكن · نقل · …             [ 0 ] %
```

> أي أن **وعاء الخصم يُبنى لكل جزاءٍ على حدة**: «50% من الأساسي + 100% من بدل
> السكن» مثلاً.

#### إذا «المعادلة» ⟵ **محرّر صيغة كامل**

| المكوّن | المحتوى |
|---|---|
| **العملة** | منسدلة عملات كاملة (دينار عراقي · أردني · دولار · يورو …) |
| **القيمة** | لوحة رموز + حقل بحث «اكتب شيئًا للبحث عنه…» |
| رموز البيانات | `الراتب الأساسي` · `أيام العمل` · `ساعات العمل` · `أيام العمل الشهرية` · `بدل سكن` · `اقتطاع سلفة` · `بدل المواصلات` · `بدل نادي صحي` · `بدل طعام` · `سكن` · `نقل` … (كل عناصر الراتب) |
| دوال | `Floor` · `Ceil` · `Round` · `Is Null` · `Null If` · `Abs` |
| شرطية | `If` · `else If` · `then` · `else` · `end` · `and` |
| مقارنات | `>` `>=` `<` `<=` `in` `,` `=` `!=` |
| لوحة أرقام | `0-9` `+` `-` `x` `÷` `(` `)` `.` `%` `c` `or` |
| تحقّق | **[إختبر الصيغة]** |

#### 4 | **أيام العمل تعتمد على** (مقام معدّل اليوم)

| الخيار | الأثر |
|---|---|
| ◉ **السنة المالية** | المقام من السنة المالية |
| ◯ **الفترات** | المقام من فترة الراتب |
| ◯ **قيمة ثابتة** | يظهر **«عدد أيام الدوام الفعلية»** [افتراضي **30**] |

ثم **«أيام العطل مستثناة من معدل فترة الراتب»**:

| الفئة | القيم |
|---|---|
| **موظفين بدون مناوبة** | `لا شيء` · `أيام عطل الشركة` · `أيام الراحة للشركة` · `أيام العطل وأيام الراحة للشركة` |
| **موظفين الحضور المنتظم** | + `أيام عطل المناوبة` |

> هذا هو الفرق بين «خصم يوم» صحيح و«خصم يوم» تقريبيّ: **المقام مُعلَن ومضبوط**،
> ومعه قرار صريح هل تُستثنى العطل من المقام.

## 7) ما أقترح نقله — مرتَّباً بالأثر

### 🔴 الطبقة الأولى — الجزاء يصير كائناً لا نصّاً (الأثر المالي الحقيقي)

1. **`PenaltyActionType` مُعدَّد** بديلاً عن النصّ الحرّ: تنبيه شفوي · تنبيه خطي ·
   إنذار · إنذار نهائي · اقتطاع من الراتب · حرمان زيادة · إنهاء الخدمة.
   النصّ الحرّ يبقى **عنواناً** للعرض، والنوع يقود السلوك.
2. **وجهة الخصم بالمسير**: عمود يربط الجزاء بعنصر راتب/بند اقتطاع قائم — بدونه
   الخصم رقمٌ لا يعرف أين يُرحَّل.
3. **وصل `SalaryBaseComposer` بالمخالفات**: وعاء الخصم يُبنى لكل جزاء (عناصر +
   نسبة لكلٍّ) بدل نسبةٍ عائمة من مجهول. الأساس مبنيّ أصلاً — ينقصه الربط.
4. **مقام أيام العمل صريح**: سنة مالية / فترة / قيمة ثابتة (افتراضي 30) + قرار
   استثناء العطل. **بدونه «خصم يوم» رقمٌ لا يُدافَع عنه أمام موظف.**

### 🟠 الطبقة الثانية — الإجراء والزمن

5. **سياسة إسقاط أغنى**: مرّة/دوريّة + وحدة (يوم/شهر/سنة) + مرساة (تاريخ الإجراء ·
   نهاية السنة المالية · نهاية السنة التعاقدية).
6. **قالب رسالة لكل درجة جزاء** + تمييز قالب **المسار الآلي** عن اليدوي.
7. **سبب الإيقاف** حين يكون الإجراء إنهاء خدمة (وصله بمودل إنهاء الخدمة القائم).

### 🟡 الطبقة الثالثة — الشكل (وهو ما لفت نظرك)

8. **شبكة محرَّرة داخل الصفّ** لشاشتي الفئات والمخالفات: زرّ يُلحق صفّاً فارغاً،
   وحفظٌ واحد للجميع، وحذف بـ✖ للصفّ غير المحفوظ.
9. **بحث داخل الشاشة** + **تحديد وحذف جماعي**.
10. **عمودان للاسم (عربي/English)** — يخدم White-Label مباشرةً.
11. **فئات نظام محميّة** لا تُحذف (الحضور والانصراف مولَّدة آلياً عندنا فعلاً).

## 8) ما لا أنصح بنقله

- **محرّر الصيغة بلوحة الأزرار الكاملة داخل مودال الجزاء**: عندنا
  `SalaryFormulaEvaluator` ومحرّر صيغ بواجهة؛ الأفضل **استدعاؤه** لا بناء ثانٍ.
- **العملة لكل جزاء**: نظامنا أحاديّ العملة؛ إضافتها هنا تعقيدٌ بلا مقابل حالياً.
- **قاعدة لكل حدوث بالضبط**: مدياتنا (`من ١ إلى ٣`) تغطّي حالتهم وتزيد، ولا داعي
