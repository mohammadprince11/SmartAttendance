## 1) الخلاصة التنفيذية (المحدَّثة)

منذ دراسة 2026-07-25 **انسكّرت كل فجوات P0 ومعظم P1**. النظام انتقل من «جاهز للحضور فقط»
إلى **«مسير رواتب اعتمادي مبني ومربوط»**. ما تبقّى للجاهزية التجارية = **تشغيل وإعداد**
بالدرجة الأولى، لا بناء ميزات.

**الحكم:** جاهز تشغيلياً للحضور + الخدمة الذاتية + إدارة الموظفين **اليوم**. المسير صار
اعتمادياً بعد ربط القروض والحضور — يحتاج **تحقّقاً حيّاً بأرقام شركة حقيقية** قبل الاعتماد
الكامل. قبل تسليم عميل خارجي: تفعيل SMTP + نسخ احتياطي/خدمة + معالج تهيئة.

## 3) الفجوات الحقيقية المتبقية (بعد التحديث)

### 🟠 تشغيل وإعداد — تمنع تسليم عميل خارجي

1. **تفعيل SMTP فعلي** ⚠️ — الكود جاهز (`SmtpEmailSender`) لكن **الإرسال معطّل حتى تُضبَط
   بيانات خادم بريد حقيقي**. الدفع (Web-Push) حيّ. → إدخال بيانات SMTP + اختبار تسليم E2E.
2. **تصليب التشغيل** ❌ — لا نسخ احتياطي/استعادة مؤتمت لقاعدة البيانات، ولا خدمة ويندوز
   حقيقية موثّقة (تشغيل عبر حلقة/عملية). → سكربت نسخ احتياطي مجدول + خدمة/NالسSM/IIS + Health endpoint.

### 🟡 اكتمال — قبل الجاهزية السوقية

3. **معالج تهيئة شركة جديدة (Onboarding)** ⚠️ — `Setup/Index` بسيط؛ يحتاج معالجاً موجّهاً
   لأول إقلاع (شركة→فروع→مناوبات→سياسات→أول أدمن).
4. **تقارير المسير النظامية** ⚠️ — تقارير الحضور/الأشخاص موجودة؛ يجب تأكيد تصدير الملفات
   النظامية (ضريبة/ضمان الرسمية) بصيغها المطلوبة.
5. **تطبيق موبايل نيتف** ❌ — يوجد أساس API (Bearer) + PWA قابلة للتثبيت فقط؛ النيتف غير مبني.

### ⚪ ديون تقنية معروفة (غير حاجزة)

6. **إعدادات المناوبات الصمّاء** — تبويب «التعارض» + معظم «القواعد» تُحفظ ولا يقرأها المحرك
   (فخّ توقّعات). الطبقة (2) الرصد النقي أُنجزت اليوم (`MovementConflictPolicy` + 8 اختبارات).
   المتبقّي = التحميل + الإصدار عبر الاقتراحات. راجع [[shift-type-dead-settings]].
7. **نظامان متوازيان للمناوبات** — القديم (`Shifts`) صار قراءة-فقط؛ الحديث (`ShiftTypes`)
   هو الرسمي. الترحيل الكامل مؤجَّل (غير حاجز). راجع [[duplicate-dead-pages-audit]].

## 5) الحكم النهائي (المحدَّث)

- **تغيّر جوهري منذ أمس:** الفجوات الحاجزة (P0) للمسير **أُغلقت**؛ النظام لم يعد «حضور فقط».
- **جاهز الآن:** الحضور · الخدمة الذاتية · الطلبات/الموافقات · إدارة الموظفين · المسير (بنيوياً).
- **الخطوة التالية الأعلى قيمة:** **تفعيل SMTP + تحقّق مسير حيّ** — بعدها النظام قابل للتشغيل
  التجاري الفعلي.
- **الفجوات الباقية تشغيلية/إعدادية لا ميزاتية** — النظام غنيّ ميزات بشكل استثنائي.
