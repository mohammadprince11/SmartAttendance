## 3. أدلة الحماية والاعتمادية

- كل استعلام موظفين معدل يطبق نطاق الشركة/البيانات قبل materialization.
- فترات الحضور المقفلة لا يعاد فتحها إلا بصلاحية وأثر تدقيق.
- الرواتب لا تقرأ حضوراً غير معتمد، وعمليات التصحيح مسيرات منفصلة.
- مسارات الكتابة الحرجة محمية بمعاملات/قيود/idempotency واختبارات تزامن SQL.
- AutoMapper المرخّص أزيل واستبدل بمحوّل داخلي حتمي مع اختبارات تكافؤ؛ لا حزمة
  مرخّصة أو مصابة بقيت في الحل.
- قاعدة كل بوابة SQL/E2E تحمل اسماً مقيداً `SmartAttendance_E2E_*` وتُحذف في
  `always()`؛ لا تستعمل قاعدة تطوير أو إنتاج.
- فحص المصدر المملوك لم يعثر على TODO/FIXME/NotImplemented/stub أو زر إنتاجي
  وهمي؛ الظهور العربي لعبارة «ينتهي قريباً» وصف عقد صحيح وليس stub.

## 4. الحدود التشغيلية التي تحتاج قرار المالك

هذه البنود لا يمكن إثباتها من فرع Git أو LocalDB، ولا يجوز إخفاؤها داخل عبارة
«100%»:

1. **اعتماد الأعمال:** يوقّع المالك أن سياسات الرواتب والضريبة والتأمين والإجازات
   تطابق لوائح الشركات الفعلية وحالاتها التاريخية.
2. **RPO/RTO والنسخ خارج الموقع:** اختبار الاستعادة الآلي أخضر، لكن جدولة نسخة
   الإنتاج ومكانها الخارجي ومدة الاحتفاظ قرارات بنية تشغيلية.
3. **الرصد والتنبيه:** health وقياسات الطلبات موجودة؛ مزود التنبيه الفعلي، وجهات
   الإشعار وعتبات القرص/5xx/فشل النسخ تحتاج إعداد البيئة.
4. **فحص malware:** التخزين محمي والروابط مقيدة، لكن محرك الفحص المؤسسي الخارجي
   وسياسة الحجر يحتاجان اختياراً وتشغيلاً في بيئة الاستضافة.
5. **دين معماري موثق:** ما زالت بعض مخازن SQL القديمة تنفذ تحقق مخطط idempotent
   وقت التشغيل داخل قفل موزع. كل مخطط جديد في هذه الدفعة بهجرة محكومة، لكن نقل
   الإرث كله من Web إلى Infrastructure/migrations برنامج تحسين مستقل لا حاجز
   وظيفي لهذه الدفعة.
