# دراسة عميقة — الاستبيانات `/Setup/CompanySurveys`

فحص حيّ 2026-08-01 بفتح باني القوالب واستخراج أسماء الحقول وأنواع الأسئلة من الـDOM.
لم يُنشأ ولم يُعدَّل أي قالب — فُتح قالب قائم وقُرئت بنيته ثم خرجتُ بلا حفظ.

**الحالة عندنا: ❌ غياب تام** — سبع شاشات لا مقابل لأيٍّ منها.

---

## 1) ⭐⭐ الاكتشاف الأهمّ: باني الاستبيانات **هو نفسه باني نماذج الطلبات**

بنية الحقول بالـDOM:

```
lstGroups[i].lstGroupFields[j]
```

وهي **مطابقة حرفياً** لما رصدناه بـ[باني الطلبات المخصصة](kayan-formbuilder-custom-requests-deep.md)
(`lstGroups[i].lstGroupFields[j]`). أي أن كيان **لا يملك بانيَي نماذج بل واحداً**
يُعاد استعماله: طلبات مخصصة · استبيانات · (والأرجح: التقييمات والمقابلات).

⟹ **الأثر التخطيطي عندنا كبير:** لو بنينا **باني نماذج عاماً واحداً**، خدم
الاستبيانات والطلبات المخصصة معاً — وهما فجوتان منفصلتان بقائمتنا. وهذا يقلب
ترتيب الأولوية: الاستبيانات ليست مشروعاً مستقلاً بل **مستهلكاً ثانياً** لباني
النماذج.

**شاشة القوالب** تقسمها ثلاث فئات، لكل واحدة «عرض القوالب»:

**أعمدة قائمة القوالب:** `اسم القالب` · `الوصف` · `نشط`، وإجراء `تعديل`

الحيّ بالديمو: قالبان — «استقصاء الرفاهية النفسية والعاطفية» و«رضاء الموظفين».

## 3) باني القالب — البنية بأسمائها الحقيقية

```
القالب
├── lstTemplateName[i].Description   ← اسم القالب بلغتين
├── Description                       ← الوصف
├── Active · FormCode · formType · IsUsed
└── lstGroups[i]                      ← مجموعة أسئلة
    ├── IsMasterGroup                 ← ⭐ مجموعة رئيسة
    ├── lstLocalization[i].Description ← اسم المجموعة بلغتين
    └── lstGroupFields[j]              ← سؤال
        ├── lstLocalization[i].Description ← نصّ السؤال بلغتين
        ├── ControlTypeID              ← نوع السؤال (10 أنواع)
        ├── Scale                      ← ⭐ سلّم التقييم (3 · 4 · 5 · 6)
        └── IsRequired
```

نصّ كيان بالشاشة: «انقر فوق **"إضافة سؤال"**، إذا كنت تريد إضافة حقول **غير
مجمعة** إلى النموذج» ⟹ السؤال قد يكون داخل مجموعة أو حرّاً بلا مجموعة.

### أنواع الأسئلة العشرة (`ControlTypeID`)

`منطقة النص` · `سؤال نعم\لا\بلا اجابة` · `قائمة منسدلة` ·
`قائمة منسدلة متعددة الاختيار` · `رقم` · `نص` · `التاريخ` · `وقت` ·
**`تقييم`** · `أرفق ملف`

مقارنةً بأنواع باني الطلبات الأحد عشر: **نفس القائمة**، ناقصةً مدَيَي
(«من–إلى تاريخ ووقت» و«من–إلى وقت») وزائدةً **«تقييم»**.

### ⭐ `Scale` — سلّم التقييم (3 · 4 · 5 · 6)

الخيار الوحيد الخاصّ بالاستبيانات. يحدّد عدد درجات سؤال التقييم، و**اختيار
السلّم قرارٌ منهجي لا تجميلي**: سلّم زوجي (4 · 6) يُجبر المستجيب على الانحياز
لأن لا وسط له، وفرديّ (3 · 5) يسمح بالحياد. جعلُه إعداداً لكل سؤال يعني أن
الشركة تختار المنهجية بنفسها.

## 4) نتائج الاستبيان — النطاق نفسه المتكرّر

`/Setup/CompanySurveys/SurveyResult_Index` — لوحة مرشّحات:

| المرشّح | الاسم البرمجي |
|---|---|
| الموظفين | `EmployeeID` |
| وحدة عمل | `BusinessUnitID` |
| الهيكلية | `HierarchyNodeID` |
| الموقع | `LocationID` |
| مجموعة الموظفين | `EmployeeGroupID` |
| كفيل | `SponsorID` |
| نوع الاستبيان | `FormTypeID` |
| القالب | `FormID` |
| الحالة (نشط/غير نشط/كلاهما) · من–إلى تاريخ | — |
| **حالة الاستجابة: `قيد الانتظار` / `تمت` / `كلاهما`** | — |

⟹ ⭐ **نفس نمط النطاق** الذي رأيناه بتوليد الوثائق وتشغيل المسير — وهو عندنا
`MassScopeResolver`. **بلا بنية نطاق جديدة.**

و«قيد الانتظار مقابل تمت» يكشف أن الاستبيان **يُرسَل ويُنتظَر**، لا يُملأ فورياً —
نفس نمط الإقرارات التي بنيناها الليلة (أُرسل ⟵ شوهد ⟵ استُجيب).

## 5) «الاستبيانات المرتبطة بحدث» — الفكرة الأذكى

شاشة مستقلة تربط قالب استبيان **بحدث بدورة حياة الموظف** بدل الإرسال اليدوي.
والدليل عليها بالبنية: فئة **«مقابلات نهاية الخدمة»** قائمةٌ بذاتها ⟹ الاستبيان
يُطلَق تلقائياً عند إنهاء الخدمة.

وهذا يلتقي بنمط كيان المتكرّر: **الأتمتة حول الأحداث** (تعيين · إنهاء · تجديد
عقد) — وهو نفسه مفتاح «أرسل تلقائياً للموظفين الجدد» بالإقرارات، الذي بنيناه.

## 7) تقديري وتوصيتي

**لا أنصح ببناء «مودل استبيانات» مستقلاً.** السبب من الفحص نفسه: باني الاستبيانات
هو باني نماذج الطلبات، والنطاق هو نطاق المسير، وتتبّع الاستجابة هو نمط الإقرارات.

**التسلسل الصحيح:**

| # | الخطوة | ما تفتحه |
|---|---|---|
| ١ | **باني نماذج عام** (مجموعات + حقول + أنواع + إلزامية + ثنائية لغة) | الاستبيانات **و** الطلبات المخصصة معاً |
| ٢ | إضافة نوع «تقييم» + `Scale` | الاستبيانات |
| ٣ | إرسال بالنطاق + تتبّع الاستجابة | يعيد استعمال `MassScopeResolver` ونمط الإقرارات |
| ٤ | ربط بحدث دورة حياة | مقابلات نهاية الخدمة تلقائياً |
| ٥ | تحليل النتائج | متأخّر ومنفصل |

**الخطوة ١ وحدها تسدّ فجوتين** من قائمة العشر، وهي الوحيدة التي تستحقّ أن تُبنى
كبنية تحتية لا كشاشة.

> ⚠️ ما لم يُفحص بهذه الجولة: شاشة **«الاستبيانات المرتبطة بحدث»** (قائمة الأحداث
> المتاحة)، وشاشة **متابعة استبيان** لموظف بعينه (كيف يراه الموظف ويجيب).
